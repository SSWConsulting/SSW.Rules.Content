AI tools can increase productivity, but they also introduce variable usage costs. Without visibility into token consumption, API calls, and agent activity, teams may unknowingly generate significant expenses.

<endIntro />

## What should be monitored?

Teams should track key indicators such as:

* Monthly AI bills (OpenAI, Anthropic, etc.)
* Token usage
* Number of agent runs
* API request volume
* High-cost workflows

Use these indicators to identify expensive workflows and decide where to optimise usage.

## Compare total spend with cost per accepted outcome

Track total spend against a budget alongside **cost per accepted outcome**: all attributable costs divided by accepted outcomes, each counted once.

* **Define acceptance first** - For example, count a published description or a resolved case after its follow-up window, rather than requests or generated drafts. Keep the acceptance definition and calculation versioned
* **Count every attempt's cost** - Include rejected attempts, retries and failed calls. Match costs to the same completed cohort of outcomes. Mark immature outcomes or unclosed charges provisional, and reconcile them later
* **State the cost basis** - Use consistent currency and allocation rules, keep unattributed spend visible, and state whether hosting and human review are included alongside model charges
* **Handle zero acceptances** - Show **No accepted outcomes** instead of zero unit cost or division by zero

For example, two completed Northwind cohorts:

| Measure | Cohort A | Cohort B |
| --- | --- | --- |
| Billed model spend | $443 | $868 |
| Accepted descriptions | 304 | 720 |
| Cost per accepted description | $1.46 | $1.21 |

This illustrates lower unit cost, not permission to breach the budget or lower acceptance quality. Reconcile spend and outcome counts independently, and investigate work-mix changes before attributing improvement to a model.

## Keep deterministic waiting outside model loops

When completion has a clear condition, let a script, native wait command or completion event handle the wait. Use the model to choose the work and interpret the final result. Repeated **still running** responses do not need another model call.

```bash
# The script waits; the model reads only the final line
status=0
timeout 30m gh run watch "$RUN_ID" --interval 30 --exit-status > ci-watch.log 2>&1 || status=$?
echo "run=$RUN_ID exit=$status log=ci-watch.log"
exit "$status"
```

**✅ Figure: Good example - A bounded script waits, keeps the polling output in a log, and returns the run ID and exit status (124 means it timed out)**

* **Bound the wait** - Identify the exact job and expected revision, set a deadline and respect rate limits
* **Return evidence** - Report success, failure or timeout with the job ID, exit status and evidence link. Use the agent environment's supported completion mechanism, because writing a file alone does not wake an agent
* **Reconcile before retrying** - A local timeout does not cancel remote work. Check its status before starting another attempt

The wait makes no model calls, but setup, interpretation, compute and service requests can still cost money.

## Providing visibility through status updates

A status line at the bottom of a CLI tool can show the current model, usage and cost while you work. Keeping these figures visible helps you spot expensive sessions without interrupting your workflow to open a dashboard.

### Customising the status line in Claude Code

Customise Claude Code's status line with a tool such as:

## Tools for monitoring AI cost and usage

Choose monitoring tools that cover both interactive sessions and production usage:

* **Native CLI commands** - Check your tool's built-in usage and status commands.

<imageEmbed alt="Claude Code /stats output showing an activity heatmap, favourite model, total tokens, sessions and streaks" size="medium" showBorder={false} figurePrefix="none" figure="Running /stats in Claude Code" src="/uploads/rules/monitor-ai-cost-and-usage/cursor-status-command.png" />

* **Provider dashboards** - Check usage and billing across sessions, including tools with a graphical interface such as Cursor and Windsurf.
* **AI observability platforms** - Track production usage, costs and model performance across applications with tools such as LangSmith, Helicone and Langfuse.
* **Custom developer tools** - Use smaller command line tools when you need more control over how usage and costs are displayed.
