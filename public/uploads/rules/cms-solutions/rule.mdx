You don’t want to build solutions from scratch, so take what business value you can from a CMS: don't reinvent the wheel.

A CMS allows business users to build and manage websites without having to write any code.

In 20+ years, SSW engineers implemented many different CMSs for clients.
In recent years, the 2 CMSs that SSW chooses most are [TinaCMS](https://tina.io) and [Contentful](https://www.contentful.com).

## TinaCMS vs Contentful

TinaCMS and Contentful are both headless CMSs, so they are not attached to a front end.
You can use any front end with them: a web app (e.g. Angular or React), a static site (e.g. Astro), or a mobile app.

SSW liked TinaCMS so much that it bought the company.

| | [TinaCMS](https://tina.io) | [Contentful](https://www.contentful.com) |
| --- | --- | --- |
| **Where your content lives** | Markdown files in your GitHub repo, next to your website code. You own the content and the code | In Contentful's cloud. You get it through their API as JSON. An export CLI dumps the whole space into 1 big JSON file |
| **Visual editing** | ✅ Out of the box. Go to `/admin` on your site to get the editor on the left and the preview on the right | ⚠️ Developers must set up content preview first. With the Live Preview SDK, your changes update as you type. Contentful Studio (a drag and drop page builder) is an add-on to the enterprise plan |
| **Publishing** | Each save makes a commit to GitHub. Your site builds automatically and the change is live in minutes | Changes autosave as you go, then you publish them |
| **Editorial workflow** | ✅ On the Tina Cloud Team plan, someone on your team reviews and approves each change before it goes live | ✅ Workflows |
| **AI** | Any AI agent can work with the Markdown files directly. The TinaCMS CLI sets up the project and manages the CMS. The Tina Cloud CLI lets your agents work with Tina Cloud (e.g. create a project) | Official MCP server and CLI |
| **Free plan** | Open source, so you can self-host it for $0. The Tina Cloud free plan has unlimited collections, 2 users and 100 GB bandwidth a month, with visual editing | 10 users, 2 roles and 50 GB bandwidth a month. The free Starter space caps you at 25 content types, 2 environments and 10,000 records |
| **Cheapest paid plan** | $29 a month per project ($290 a year) | $300 a month (Lite plan). For more content types or records, a Lite space costs $850 a month on top, and you can buy only 1. After that, you must move to the enterprise plan |
| **Version history** | Git history. Every save is a commit, so you see who changed each line. You can revert a change | Each publish saves a snapshot. Compare versions side by side, and restore 1 field or the whole entry. Only the master environment records history |

**Source:** [tina.io/pricing](https://tina.io/pricing) and [contentful.com/pricing](https://www.contentful.com/pricing), checked 2 November 2026. Prices in USD.

### Let AI work with your content

With TinaCMS, your content is Markdown in the same repo as your website code.
So you can ask your AI agent to build a custom component, update the schema, and edit the content in 1 change.

### ✅ Example: SSW Rules runs on TinaCMS

[SSW Rules](https://www.ssw.com.au/rules) has more than 3,000 rules, all edited with TinaCMS.

* **Every save is a commit** - The commit history shows who made each change, line by line
* **Every change gets a review** - SSW Rules uses the TinaCMS editorial workflow, so you see who reviewed and approved each change
* **You can undo any change** - Revert it, and the old content comes back

## Headless CMS vs Traditional CMS

A Traditional CMS is a monolith, which means it has both a front-end and back-end. It uses server side technology like PHP (Wordpress, Joomla, Magento) or ASP.Net (DNN, Umbraco, Sitefinity) and a single database. All pages are served by one or many backend servers.

A Headless CMS deals strictly with the content. Created content is accessed via Application Programming Interfaces (APIs), which gives you full flexibility on how you build the front-end for your website.

For example, you can use a Headless CMS with a super fast Static Site Generator (SSG): see the rule on the [best static site tech](/best-static-site-tech-stack).

**Source**: [UDig - Traditional CMS vs Headless CMS](https://www.udig.com/insights/article/traditional-cms-vs-headless-cms)

### ✅ Traditional CMS - Pros

* **Simple and fast** - For setup and maintenance
* **Less reliance on developers** - You won't be as reliant on developers to make changes, and may be able to forgo them completely for small-medium projects. More complex CMSs will require developer involvement but non-developers still have some customisation control
* **Simple to control look and feel** - Using available themes and templates
* **Large community support**
* **Out of the box integrations** - Payments, social media, etc

### ❌ Traditional CMS - Cons

* **Performance is not amazing** - The frontend is coupled with the backend
* **Does not scale very well** - All pages render server side, so you will need more servers if you have lots of traffic
* **Locked-in** - Content is only available on browsers and not on native mobile apps
* **Limited flexibility** - You are limited to themes and templates, e.g. if you want to build a multi-step form
* **You need developers with particular CMS skills** - If you have a big website or are using complicated CMS features, you will need CMS developers - e.g. for SiteCore or Sitefinity
* **It is not an API first solution**

### ✅ Headless CMS - Pros

* **Super fast** - Fast initial load time when using Static Site Generator (SSG)
* **Scales very well** - When using Static Site Generator, and the frontend can be cached via CDN
* **Ultimate flexibility with how to use content** - Can use a Single Page Application (SPA), Static Site Generator (SSG) or even native mobile apps. Not restricted by themes, templates or vendor, and you can have multiple frontends with 1 headless CMS backend
* **Many options to build frontend** - Next.js, Astro, Hugo, React, Angular, etc. This makes it easier and cheaper to find developers
* **Easy publishing** - The same content can be published to different platforms at the same time (website, web app, native mobile app)

### ❌ Headless CMS - Cons

* **Very reliant on frontend developers** - Anything beyond basic content changes will require frontend dev involvement
* **Greater overhead** - To maintain the code base, DevOps, etc
* **Preview can need extra setup** - Many headless CMSs need developers to set up a preview first (e.g. Contentful). TinaCMS has visual editing out of the box

## Hybrid CMS

Some CMSs (e.g. [Optimizely](https://www.optimizely.com)) offer a hybrid approach including both headless integration and a fully featured UI. As such, you can get the best of both worlds by going down this route. However, pursuing this option comes at a premium with prices matching or exceeding traditional CMSs. An entry level figure for Hybrid CMSs is approximately $50,000 but this figure can quickly increase to several hundred thousand $ as you include add-ons and other features.
