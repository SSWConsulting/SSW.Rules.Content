An AI assistant builds an operations dashboard in an afternoon. It looks finished, but nobody can trace its 77% accuracy figure to a source or find how many answers were checked. The AI commentary already recommends a rollback.

**Build the dashboard on saved calculations and require evidence for its insights.** Let code refresh the figures and use AI to suggest what a person should investigate.

## Build for one audience

Choose the few questions that audience needs answered. Give the assistant your [design system](/ai-with-design-system), including colours, type and spacing, so readers can recognise the page and use it consistently.

## Let code own the numbers

Give each recurring metric a stable name, such as `support_agreement_v1`. Keep its query, filters, denominator and tests in source control. Bind the tile to that saved calculation; a language model never types an actual figure into the daily page. [Named measures](https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-measures) are one implementation of reusable calculations.

Show the source, coverage date and a route to the metric definition beside the result. Refreshing the figures makes no language-model call, so an AI outage leaves the data refresh working. Use the same saved results in the insight panel; render referenced values from those results rather than copying AI-written numbers.

Before readers rely on the page:

* [Remove sample data and dead controls](/remove-fake-data-from-ai-built-dashboards)
* [Reconcile totals independently](/check-dashboard-totals-against-the-source)
* [Expose missing and stale data](/show-missing-and-stale-data-on-dashboards)
* [Show sample size and coverage](/show-coverage-on-ai-quality-dashboards) beside quality rates

## Use an agent for a one-off question

An agent can investigate a question with read-only SQL on an approved local or sanitised database; see [safe database access for AI agents](/ai-database-access). Check its query and result before using the answer. When that answer becomes a daily tile, [build the report to be reused](/do-you-create-a-report-whenever-you-need-a-number-from-a-system) and move the reviewed query into the saved metric code.

## Schedule insights with evidence

Run AI daily or weekly, matching when someone acts. Supply the saved metrics and relevant prompt, model and data changes. Each insight needs a metric reference, a suggested next check and its own generation time. Keep the last insight visibly dated if generation fails.

A release marker shows timing, not cause. Allow **No clear change yet**, and [test changes before colouring trends](/dashboard-changes-real-or-noise). Label AI-derived classifications, such as chat themes, and check a sample against a written rubric. Human agreement alone does not prove correctness; [review disagreements against source evidence](/disagreement-inbox-for-ai-quality).

Add [backtested forecasts](/forecasts-in-ai-dashboards) and [cost per useful outcome](/track-ai-cost-by-total-and-unit) when those decisions matter to this audience.
