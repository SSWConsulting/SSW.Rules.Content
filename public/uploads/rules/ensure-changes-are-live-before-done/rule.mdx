When working on a website or application, completing your development work does not necessarily mean the changes are live. They may still be waiting for approval, merging, or deployment.

Before marking a task as Done, always ensure the changes have been approved, successfully deployed, and are available for others to verify.

<endIntro />

Marking a task as Done too early can cause several problems:

* **Confusion** - Stakeholders expect to see the completed changes, but they are not yet available
* **Wasted time** - Reviewers spend time looking for changes that have not been released
* **Unnecessary communication** - People ask why the changes are missing, generating avoidable emails and messages
* **False confidence** - Changes awaiting approval, merging, or deployment are not necessarily ready for production. The approval might be rejected, or the deployment might fail
* **Missed issues** - Changes that work in development might fail in production. Marking the task as Done too early can leave these problems unnoticed
* **Loss of trust** - Repeatedly claiming work is complete when it cannot be verified reduces confidence in your Done messages

## Steps to take before sending a Done

1. **Get approval** - Ensure all required approvals have been received
2. **Confirm the release** - Verify the changes have been merged or released
3. **Check deployment** - Wait for the deployment pipeline to complete successfully
4. **Verify production** - Open the production URL and confirm the changes are visible and working as expected
5. **Send your Done** - Include the final URL so others can easily verify the changes

## Use clear status wording for unfinished work

If your work is not yet live, communicate its current status instead of calling it Done. This keeps stakeholders informed without giving the impression that the task is complete.

[Use emojis](/use-emojis) and wording such as:

* 👀 **In Progress** - The changes are still being worked on
* 👀 **Pending Review** - The changes are ready for review, but have not yet been approved
* 👀 **Pending Approval** - The work requires approval before it can proceed
* 👀 **Pending Merge** - The PR has been approved but has not yet been merged
* 👀 **Pending Deployment** - The changes have been merged but are not yet live
* 👀 **Pending Verification** - The changes have been deployed but still need to be checked in production
* 🚫 **Blocked** - The work cannot proceed until an issue or dependency is resolved
