Northwind Traders' support lead changes the date range on a new AI-built operations dashboard, but nothing moves. Sample escalations sit beside real customers, and the health badge never changes. The page was shared before anyone checked which parts were real.

That's why you should **remove sample data and dead controls before sharing an AI-built dashboard**.

## Keep samples out of live mode

Sample data helps AI draw a page before a source connects. Keep it in a separate sample mode. Never substitute sample rows when live data is unavailable. Mixing sample rows into real results makes even a connected dashboard untrustworthy.

If a panel cannot be computed, leave it empty and explain why. Northwind's returns panel says the inbox is not connected yet. See [Do your dashboards say when data is missing or stale?](/show-missing-and-stale-data-on-dashboards).

## Wire every control or delete it

A selected filter promises that the results reflect that selection. A button promises an action. A dead filter leaves the reader looking at the wrong period without knowing it.

Northwind deletes the fake filter chips and lasso and keeps two working dropdowns, Feature and Dates. The escalation list loses its dead Auto-resolve buttons.

## Make the mode visible

Label the page as live or sample data, with the time the data was built. Read health figures from the build results instead of typing a reassuring badge into the layout. Northwind's footer reports 2,371 of 2,412 emails parsed (98.3%) and says sample data is off.

## Try the page before sharing it

Change the date range to one with different records and check that each affected number responds correctly. Click every control and confirm its result. Turn off a data source and check that its panel explains the gap without filling it with samples.

For connecting the live data sources, see [Do you use AI to generate useful dashboards with insights?](/ai-dashboards-with-insights).
