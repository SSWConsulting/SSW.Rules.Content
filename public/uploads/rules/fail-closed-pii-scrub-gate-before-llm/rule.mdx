A support-ticket summariser can remove customer names and contact details before calling a large language model (LLM), yet still leak them during an outage. If its exception handler continues with the original text, the privacy control disappears precisely when it fails.

When personal data must be removed before a model call, make the scrub step **fail closed**: errors, timeouts and unconfirmed results block the call. A temporarily unavailable summary is safer than sending the raw ticket.

<endIntro />

## Require an explicit release decision

[De-identifying data](/de-identified-data) describes what to remove. This rule addresses what happens when that removal cannot be completed or verified: **no approved scrub result means no model request**. This applies [OWASP's fail-securely principle](https://owasp.org/www-community/Fail_securely) to the boundary before the LLM.

Put the gate in a shared server-side model wrapper, after assembling all variable prompt content, including retrieved passages and conversation history. Send only the approved output; adding the original ticket as extra context defeats the gate. Retries and alternate model routes must pass through the same boundary.

Use a scrubber adapter that approves output only after processing the entire input under your configured entity, language and confidence rules. Unsupported input, partial processing, malformed responses and uncertain detections remain blocked. An HTTP success or an empty detection list alone does not establish that all required checks ran.

[Presidio](https://presidio.dataprivacystack.org/) provides PII detection and de-identification components, and [Azure AI Language PII detection](https://learn.microsoft.com/en-us/azure/ai-services/language-service/personally-identifiable-information/overview) can detect and redact text. These are implementation options, not guarantees: Presidio explicitly warns that automated detection can miss sensitive information. Approval means the configured checks passed, not proof that no personal data remains. Evaluate detection quality with representative synthetic cases, minimise input, and use an approved processing environment for the scrubber itself.

## Block the call when the scrubber fails

**Example data:** Northwind receives a fictional ticket: “Mira Vale, `mira.vale@example.com`, +1 202-555-0142: my parcel arrived damaged.” Both examples use the same ticket and injected scrubber/model functions.

```typescript
async function summariseBad(text: string, scrub: Scrubber, model: Model) {
  try {
    const result = await scrub(text, new AbortController().signal);
    if (result.status === "approved") text = result.text;
  } catch {
    // Continue even though the privacy check failed.
  }
  return model(text);
}
```

The corrected TypeScript wrapper below bounds the wait and requires an explicit approval. `record` is an injected metrics/logging function; it receives only fixed decision and reason codes. `Scrubber` is an application contract, not a vendor SDK response.

```typescript
type ScrubResult =
  | { status: "approved"; text: string }
  | { status: "blocked" };
type Scrubber = (text: string, signal: AbortSignal) => Promise<ScrubResult>;
type Model = (text: string) => Promise<string>;
type Reason = "approved" | "scrubber_error" | "scrubber_timeout" | "unconfirmed";
type RecordDecision = (decision: "allowed" | "blocked", reason: Reason) => void;

class ScrubTimeout extends Error {}
export class PrivacyGateBlocked extends Error {
  constructor() {
    super("Summary blocked: privacy check unavailable or unconfirmed.");
  }
}

export async function summarise(
  text: string, scrub: Scrubber, model: Model, record: RecordDecision,
  timeoutMs = 2_000
) {
  const controller = new AbortController();
  let timer: ReturnType<typeof setTimeout> | undefined;
  let result: ScrubResult;
  try {
    const deadline = new Promise<never>((_, reject) => {
      timer = setTimeout(() => {
        reject(new ScrubTimeout());
        controller.abort();
      }, timeoutMs);
    });
    result = await Promise.race([scrub(text, controller.signal), deadline]);
  } catch (error) {
    record("blocked", error instanceof ScrubTimeout
      ? "scrubber_timeout" : "scrubber_error");
    throw new PrivacyGateBlocked();
  } finally {
    clearTimeout(timer);
  }

  if (result?.status !== "approved" || typeof result.text !== "string") {
    record("blocked", "unconfirmed");
    throw new PrivacyGateBlocked();
  }
  record("allowed", "approved");
  return model(result.text);
}
```

The two-second timeout is an example, not a service requirement. The race stops waiting even if the scrubber ignores cancellation; a late result cannot resume the model call. Keep the scrubber free of model-call side effects. Map `PrivacyGateBlocked` to a clear user message or a deterministic fallback such as “Summary unavailable; view the ticket in the support system.” Never retry with raw text or send it to another model as a fallback.

## Test zero outbound model calls

Save the good wrapper as `gate.ts` and the test as `gate.test.ts`. Run `node --test gate.test.ts` with Node.js 24. The test forces the scrubber to throw an exception containing the fictional ticket and checks the outward error, metric and model-call count.

```typescript
import test from "node:test";
import assert from "node:assert/strict";
import { summarise, PrivacyGateBlocked } from "./gate.ts";

test("scrubber failure blocks the model without logging the ticket", async () => {
  const ticket = "Mira Vale, mira.vale@example.com, +1 202-555-0142: damaged parcel";
  let modelCalls = 0;
  const events: string[][] = [];

  await assert.rejects(summarise(
    ticket,
    async () => { throw new Error(ticket); },
    async () => { modelCalls++; return "summary"; },
    (decision, reason) => { events.push([decision, reason]); }
  ), PrivacyGateBlocked);

  assert.equal(modelCalls, 0);
  assert.deepEqual(events, [["blocked", "scrubber_error"]]);
});
```

**Figure: A forced scrubber error produces one safe blocked event and zero model calls**

Before releasing the gate:

* Test a never-resolving scrubber, a late success after timeout, an unconfirmed or malformed result, and a partial-processing failure: each must produce zero model calls
* Test successful redaction: the model receives only the expected scrubbed text, with no raw ticket reattached
* Check logs, traces and exception reporting as well as metrics. Record a server-generated correlation ID and fixed reason codes, never the ticket, detected values or scrubber exception message. Disable prompt/body capture on this route; follow [OWASP's logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#data-to-exclude)
* Alert on blocked-decision rates and investigate availability or detection problems without weakening the gate

This controls one disclosure path. [OWASP LLM02:2025](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/) also recommends input validation, redaction and restricted data access; keep those protections alongside [broader AI security controls](/manage-security-risks-when-adopting-ai-solutions).
