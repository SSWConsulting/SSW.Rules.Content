You write a prompt for a recurring task, then never revisit it. Reviewers keep correcting the same mistake, run after run. Their corrections fix individual answers, but the next run starts with the same instructions.

Save what you learn in the prompt, then check that the change helps.

<endIntro />

## Treat the prompt as a playbook

[Agentic Context Engineering (ACE)](https://www.microsoft.com/en-us/research/publication/agentic-context-engineering-evolving-contexts-for-self-improving-language-models/) (Zhang et al., ICLR 2026; [arXiv:2510.04618](https://arxiv.org/abs/2510.04618)) treats context as an evolving playbook. It accumulates, refines and organises strategies through generation, reflection and curation, using structured, incremental updates instead of rewriting everything.

ACE works offline on system prompts and online on agent memory. It can adapt from natural execution feedback without labelled data.

The paper names two traps: "brevity bias", where summaries drop domain detail, and "context collapse", where repeated rewrites erode it. Keep useful detail and change the entry that needs fixing.

## The loop

1. Run the task with the current prompt.
2. Capture feedback: reviewer corrections, failed checks or a user's thumbs-down. Keep the input and output so you can inspect the failure.
3. Reflect on what went wrong. Identify the missing instruction rather than copying the corrected answer.
4. Curate a small, specific playbook entry. Add or edit one bullet; don't rewrite the whole prompt.
5. Re-run evals before promoting the new version. Check earlier cases as well as the failure that prompted the change.

## Optimise against a metric when you have one

[DSPy's GEPA optimizer](https://dspy.ai/api/optimizers/GEPA/overview/) uses an LLM to reflect on execution traces and textual feedback from your metric, propose new instructions, and keep a Pareto frontier of candidates. It needs a metric plus training and validation examples.

Use GEPA when you have a scored dataset. Use ACE-style playbooks when your feedback is mostly unscored corrections; you still need evals before promoting changes.

## Guardrails

* Version the prompt in git like code.
* Gate every promotion on evals. See [Do you run evals on your AI features?](/run-evals-on-ai-features).
* Keep a human approving entries at first.
* Prune entries that stop earning their place.
* Mind [prompt caching](/do-you-follow-best-practices-for-prompt-caching): append-only edits near the end keep the earlier cached prefix stable.
* When the playbook grows large, move details into a [skill's extra files](/ai-agents-with-skills) so they load on demand.
