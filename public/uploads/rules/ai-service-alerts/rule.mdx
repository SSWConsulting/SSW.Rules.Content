Most teams put a budget alert on the Azure subscription and stop there. But cost data arrives with a delay, and a budget says nothing when the AI model starts rejecting requests or returning errors. Users get slow or failed answers long before anyone on the team knows.

That's why every project with an AI feature should **set alerts on the AI service itself: throttling, failures and token usage**.

<boxEmbed

  body={<>
    | Alert | Metric in Azure Monitor | Fires when |
    | --- | --- | --- |
    | Throttling | Azure OpenAI Requests, status code 429 | More than 10 in 5 minutes |
    | Failures | Azure OpenAI Requests, server errors | More than 5 in 5 minutes |
    | Token spike | Processed Prompt Tokens and Generated Completion Tokens | Usage is far above its normal level (dynamic threshold) |
  </>}

/>

## Make every alert lead to an action

1. **Send it to the team** - Alerts go to [the project's Teams channel](/set-up-azure-alert-emails-on-teams-channel)
2. **Say what to do** - Put the first step in the alert description (e.g. "Find the deployment that is throttling, then raise its TPM")
3. **Handle 429s in code too** - [Retry with backoff](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/quota) and respect the `retry-after-ms` header, so a short burst never reaches the user
