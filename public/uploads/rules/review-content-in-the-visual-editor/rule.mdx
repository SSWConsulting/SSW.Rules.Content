When someone reviews a content change, they need to see the page as it will look on the site. A raw MDX diff only shows which lines changed, and GitHub's markdown preview leaves out MDX components. Review content changes in your CMS visual editor instead, where you see the real page and can fix it in the same place.

<endIntro />

<boxEmbed
  style="greybox"
  body={<>
    ### Reviewing the raw MDX diff

    The diff shows which lines changed, but not how the page will look. The reviewer has to picture the layout and the components in their head.

    ![](/uploads/rules/review-content-in-the-visual-editor/blog-change-git-diff.png)
  </>}
  figurePrefix="bad"
  figure="A raw diff shows the text and tags that changed, not the page"
/>

<boxEmbed
  style="greybox"
  body={<>
    ### Reviewing the GitHub markdown preview

    GitHub's preview styles the headings, links and paragraphs, so it reads better than the diff. Custom MDX components like images and callouts are missing, and you can't fix anything from the preview.

    ![](/uploads/rules/review-content-in-the-visual-editor/blog-change-github-preview.png)
  </>}
  figurePrefix="ok"
  figure="Better, but not perfect. GitHub's preview styles the text, but MDX components don't show"
/>

<boxEmbed
  style="greybox"
  body={<>
    ### Reviewing in the CMS visual editor

    Send the reviewer the visual editor link for the branch, plus the pull request. They see the page exactly as it will look, and can fix a sentence in the same place. Each save commits to the branch.

    ![](/uploads/rules/review-content-in-the-visual-editor/blog-change-tina-visual-editor.png)
  </>}
  figurePrefix="good"
  figure="The TinaCMS visual editor shows the real page, and you can edit it in the same place"
/>
