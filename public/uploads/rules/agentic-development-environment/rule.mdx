Claude Code fixes a bug in 1 terminal. Codex builds a feature in another. A 3rd agent writes tests in a different repository. One waits for your answer, one has a pull request with failing CI, and you click through every window to find out which is which.

Your tools assume a human who writes code 1 file at a time. That is no longer the job.

## What is an ADE?

An **Agentic Development Environment (ADE)** is a workspace built around agents that write the code. You direct, review and ship their work. Other names are "agent development environment" and "agent IDE".

An **Integrated Development Environment (IDE)** such as [JetBrains Rider](https://www.jetbrains.com/rider/), [Visual Studio](https://visualstudio.microsoft.com/) or [Visual Studio Code](https://code.visualstudio.com/) puts a person who types at the centre. Its best features are autocomplete, refactoring and a debugger. AI came later, as a chat panel on the side.

An ADE flips that layout. Agent sessions are the centre of the screen, and the editor is where you review what the agents wrote.

| | IDE | ADE |
| --- | --- | --- |
| **Who writes the code** | You, with AI suggestions | Agents, directed by you |
| **Unit of work** | A file | A task, in its own session and branch |
| **Concurrency** | 1 thing at a time | Many agents across many projects |
| **Main screen** | Code editor | Agent sessions, diffs and pull request status |

## Why IDEs are obsolete

When agents write the code, the bottleneck moves from typing to coordinating and reviewing. An IDE does not help with either:

* **1 task at a time** - Several agents mean several IDE windows, several terminals and constant context switching
* **No agent status** - You cannot see which session works, which waits for you and which is done
* **Pull requests live somewhere else** - You check the browser again and again for CI and review status
* **The wrong user** - Autocomplete and refactoring shortcuts do not help when you are not the one who types

An agent panel on the side of an IDE does not fix this. The layout still serves 1 person who edits 1 file.

## What should an ADE do?

* **Show agent status at a glance** - Working, waiting for input, or done. It alerts you when an agent needs you
* **Isolate each task** - Each task gets its own [git worktree](/git-worktrees) and branch, so agents do not change the same files
* **Run agents from any provider** - [Claude Code](https://claude.com/product/claude-code), [Codex](https://developers.openai.com/codex/cli), [GitHub Copilot CLI](https://github.com/features/copilot/cli/) and other [AI CLI tools](/ai-cli-tools) side by side. No model is best at everything
* **Track pull requests** - Finished work becomes a pull request, and the ADE shows its CI checks and review status
* **Help you review** - A diff viewer lets you comment on a line and send the comment back to the agent. You are still responsible for every line you merge

## Desktop ADE or terminal ADE?

Both kinds run the same CLI agents. The difference is where you review the work.

| | Desktop ADE | Terminal ADE |
| --- | --- | --- |
| **What it is** | A GUI app with sessions, diffs, pull requests and a browser in 1 window | A terminal multiplexer that knows the state of each agent |
| **Review** | Built-in diff viewer and PR panel | Your own tools (`git diff`, your IDE, GitHub) |
| **Best for** | Most developers, and anyone who reviews a lot of code | Keyboard-first developers, and agents on a remote server over SSH |
| **Examples** | Orca, Paradev, T3 Code, Herdr app | Herdr, cmux, tmux |

## Which ADE should you use?

Start from how you work:

* **You want 1 window for agents, diffs and pull requests** - [Orca](https://orca.dev/) (⭐ Recommended)
* **You live in the terminal, or run agents on a server** - [Herdr](https://herdr.dev/) (⭐ Recommended)
* **You use only Claude, or only Codex** - The vendor's own app is enough: [Claude Code desktop](https://code.claude.com/docs/en/desktop) or the [Codex app](https://learn.chatgpt.com/docs/app). You cannot mix providers
* **Your team works in VS Code with GitHub Copilot** - The [VS Code Agents window](https://code.visualstudio.com/docs/agents/run/agents-window)

### Compare the options

| Tool | Type | OS | Price | Agents | Remote and mobile |
| --- | --- | --- | --- | --- | --- |
| [Orca](https://orca.dev/) ⭐ | Desktop | macOS, Windows, Linux | Free, open source (MIT) | 30+ CLI agents | SSH, iOS and Android apps |
| [Herdr](https://herdr.dev/) ⭐ | Terminal and desktop | macOS, Windows, Linux | Free, open source (Apache 2.0) | About 25 CLI agents | SSH, iOS and Android apps |
| [Paradev](https://github.com/ParadevAI/Paradev) (was Superset) | Desktop | macOS (Linux experimental) | Free, open source (MIT). Paid Pro plan | 20+ CLI agents | Remote hosts. iOS app needs Pro |
| [T3 Code](https://t3.codes/) | Desktop and web | macOS, Windows, Linux | Free, open source (MIT) | Claude Code, Codex, Cursor and more | Web, iOS and Android |
| [Paseo](https://paseo.sh/) | Desktop and web | macOS, Windows, Linux | Free, open source (Apache 2.0) | 10+ CLI agents | Web, iOS and Android |
| [Emdash](https://emdash.com/) | Desktop | macOS, Windows, Linux | Free, open source (Apache 2.0) | 9+ CLI agents | SSH |
| [cmux](https://cmux.com/) | Terminal app | macOS only | Free, open source (GPL 3.0) | Any CLI agent | SSH |
| [Claude Code desktop](https://code.claude.com/docs/en/desktop) | Desktop | macOS, Windows (Linux beta) | Paid Claude plan | Claude only | Cloud sessions, mobile |
| [Codex app](https://learn.chatgpt.com/docs/app) | Desktop (in ChatGPT) | macOS, Windows (Linux preview) | ChatGPT plan | Codex only | Remote, mobile |
| [VS Code Agents](https://code.visualstudio.com/docs/agents/run/agents-window) | Desktop (in VS Code) | macOS, Windows, Linux | Needs GitHub Copilot | Copilot, Claude, Codex | SSH, tunnels, cloud sessions |

All these tools give each task its own worktree.
