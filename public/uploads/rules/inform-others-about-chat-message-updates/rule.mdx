Editing a chat message is useful for fixing mistakes or clarifying information. However, changing a message after someone has read or reacted to it can cause confusion.

Most chat applications, including Microsoft Teams, give a subtle indication, but do not send a new notification when you edit a message. This means someone may continue working with outdated information without realizing it has changed.

When making a **meaningful change**, make sure others know about it. If someone has already reacted to your message, leave the original unchanged and send a new message instead.

<endIntro />

## When should you edit a message?

* **Minor typo or formatting fix** - Edit the message without sending a notification if the meaning stays the same
* **Message not yet read** - You can edit it without notifying others, provided nobody has already responded or reacted
* **Meaningful change to a message already read** - Edit the message and send a follow-up explaining what changed
* **Message already reacted to or answered** - Leave the original unchanged and send a v2 instead

### Notify others when you make a meaningful change

If you edit a message that changes its meaning, instructions, or important details, send a follow-up message explaining what changed.

For example, imagine you send a message asking someone to review a PR, but later realize the PR is not ready.

<boxEmbed
  style="greybox"
  body={<>
    **Original message:**
    
    > The PR is ready for review. Please take a look.\
    > github.com/Northwind/pull/1234
    
    **Edited message:**
    
    > The PR is not ready for review yet. Please wait until the build passes.\
    > github.com/Northwind/pull/1234
  </>}
  figurePrefix="bad"
  figure="The message was silently edited, so someone who read the original may start reviewing a PR that is not ready"
/>

<boxEmbed
  style="greybox"
  body={<>
    **Edited message:**
    
    > The PR is not ready for review yet. Please wait until the build passes.\
    > github.com/Northwind/pull/1234
    
    **New message:**
    
    > Updated my message above. The PR is **not** ready for review yet. Please wait until the build passes.
  </>}
  figurePrefix="good"
  figure="A follow-up message makes the change visible and explains why the original instructions no longer apply"
/>

### Never change the meaning of a message after someone has reacted

A reaction, such as a 👍, is feedback on the message as it was originally written.

If you change the meaning of that message afterward, the reaction may appear to support something the person never intended.

<boxEmbed
  style="greybox"
  body={<>
    **Original message:**
    
    > In my summary video, is my work on TinaCMS worth mentioning? Or should I omit it based on most interns not having that option?
    
    👍 Adam's reaction
    
    **Edited message:**
    
    > Edited - In my summary video, is my work on TinaCMS worth mentioning?
    
    👍 Adam's reaction
  </>}
  figurePrefix="bad"
  figure="Editing the ambiguous question can change Adam's 👍 intention (e.g. Adam may have agreed that the TinaCMS work should be omitted"
/>

<boxEmbed
  style="greybox"
  body={<>
    **Original message (unchanged):**
    
    > In my summary video, is my work on TinaCMS worth mentioning? Or should I omit it based on most interns not having that option?
    
    👍 Adam's reaction
    
    **New messages:**
    
    > v2 (separated messages as per [https://www.ssw.com.au/rules/separate-messages](https://www.ssw.com.au/rules/separate-messages))\
    > \
    > In my summary video, is my work on TinaCMS worth mentioning?
    
    > OR\
    > Should I omit it based on most interns not having that option?
  </>}
  figurePrefix="good"
  figure="The original question is preserved, while a new v2 allows Adam to react to the correct option"
/>
