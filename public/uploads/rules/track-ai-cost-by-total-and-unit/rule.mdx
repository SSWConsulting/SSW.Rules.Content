An AI feature's spend nearly doubles and its dashboard turns red. Is that waste, or does the feature produce more than twice as much useful work? A total or cost per request cannot inform that decision.

**Track total AI spend for the budget and cost per useful outcome for value.** Define useful before comparing models or prompts.

## Track the total for the budget

Keep an [overall spend budget](/azure-budgets) and [an owner for investigating alerts](/finops-owner). In Azure Cost Management, [cost data typically takes 8–24 hours for Enterprise Agreement and Microsoft Customer Agreement subscriptions, or up to 72 hours for pay-as-you-go](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/understand-cost-mgt-data#cost-and-usage-data-updates-and-retention).

Retry storms or runaway loops can accumulate charges during that delay, so add [real-time alerts for request volume, failures and throttling](/ai-service-alerts) alongside the budget alerts.

For developer subscriptions and token activity, see [monitoring AI cost and usage](/monitor-ai-cost-and-usage). This rule adds a measure of useful output from an AI feature.

## Define and count useful work

Choose a measurable acceptance criterion: a description published without edits, or a support case resolved without reopening during a defined follow-up period. A token, request or generated draft counts activity, not success.

Divide all attributable feature costs, including rejected attempts, retries and failed calls, by accepted outcomes counted once. This is [unit economics](https://www.finops.org/framework/capabilities/unit-economics/): cost expressed against useful output. Make the calculation comparable and its limits visible:

* Keep the same currency, cost basis and attribution policy across periods.
* Allocate shared-deployment costs using [recorded feature tags](/apply-tags-to-your-azure-resource-groups) or another documented allocation rule. Keep unattributed cost visible.
* State whether the figure covers model charges only or also hosting and human review. Omitted costs limit the value claim.

Align costs with their outcomes. If publishing or resolution takes days, use a completed cohort and its associated costs, or flag a provisional period until outcomes mature. Label provisional charges as estimates and reconcile them once billing closes. **No accepted outcomes** is a visible state, not a zero unit cost or division by zero.

## Save and review the calculation

Keep `cost_per_accepted_description_v1`, its joins and its acceptance definition in source control. For a one-off question, an agent can propose a query that a person checks for correct filters, joins and totals before using its result. A recurring daily tile uses the saved, reviewed calculation. [Reconcile both spend and accepted counts independently](/check-dashboard-totals-against-the-source) before drawing conclusions.

## Compare cost per accepted description across completed cohorts

Northwind compares completed product-description cohorts for 14–20 September and 9–15 October. The example uses billed model charges only, including rejected drafts:

* Spend rises from **$443 to $868**, up 96%
* Accepted descriptions rise from **304 to 720**, up 137%
* Cost per accepted description falls from **$1.46 to $1.21**, down 17%

Lower unit cost does not excuse a budget breach or lower quality. Keep acceptance criteria comparable, mark changes and investigate shifts in work mix before attributing the improvement to a model or prompt. Run [quality evals](/run-evals-on-ai-features) before accepting a cheaper alternative.

Put both measures on [a traceable dashboard](/ai-dashboards-with-insights) so readers can distinguish affordability from value.
