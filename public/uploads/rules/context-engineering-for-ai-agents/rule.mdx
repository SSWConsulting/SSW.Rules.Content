Your AI agent has spent an hour migrating a codebase to a new database driver. Early on, it skimmed the driver docs and wrote itself a note: the new driver retries failed connections, so the old retry code can go. The note is wrong. The agent trusts it anyway and deletes working retry code from every file it touches.

Context engineering is deciding what goes into an agent's context window at each step. Bigger windows don't fix this. Frontier models get less reliable as their window fills, a problem known as context rot. The fix is counter-intuitive: you make the agent better by giving it less.
