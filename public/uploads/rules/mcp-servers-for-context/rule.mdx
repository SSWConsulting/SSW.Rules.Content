AI coding agents come with powerful built-in capabilities, but sometimes you need to extend them further. MCP servers connect agents to external systems like databases and APIs, while skills guide agent behavior through specialized prompts. Knowing when to use each is key to an effective workflow.

<endIntro />

## When you don't need MCP

Modern AI coding agents are excellent at generating impromptu code and CLI commands on the fly. For many common tasks, you don't need an MCP server because agents already have built-in tools that handle these operations natively:

* **File operations** - Reading, writing, and searching files
* **Git commands** - Commits, branches, diffs, and history
* **Shell execution** - Running build commands, tests, and scripts
* **Web requests** - Fetching documentation or API responses

MCP servers become valuable when you need **persistent, specialized integrations** - such as connecting to databases, searching with specific APIs, or interacting with platforms like GitHub in a structured way.

## Skills as an alternative

Skills (also known as slash commands) are another way to extend AI coding assistants. Unlike MCP servers which provide tool access to external systems, skills inject specialized prompts and workflows that guide the AI's behavior for specific tasks.

### When to use Skills vs MCP Servers

Use **Skills** when you need to guide the AI's behavior without external access:

* When working with a proprietary or domain-specific language (DSL) or internal framework that is unlikely to be well-represented in the AI's training data
* Standardizing commit message formats
* Enforcing code review checklists
* Following team coding conventions
* Generating boilerplate with specific patterns

Use **MCP Servers** when you need to connect to external systems:

* Querying a live database
* Interacting with GitHub Issues/PRs
* Searching external APIs (e.g. Brave Search)
* Running browser automation

### Best practices for Skills

* **Use skills for workflow standardization** - When you want consistent outputs like commit messages, PR descriptions, or code following specific patterns
* **Keep skills focused** - Each skill should do one thing well rather than trying to handle multiple scenarios
* **Prefer skills for prompt injection** - If you just need to guide the AI's approach or provide context without external system access, skills are simpler to set up than MCPs
* **Combine with MCP when needed** - Skills and MCP servers work well together. Use skills to define the workflow and MCP servers to provide the data access

### Example: Claude Code custom slash commands

Claude Code allows you to create custom slash commands by adding markdown files to your project's `.claude/commands/` directory:

## Recommended MCP Servers

* [GitHub MCP Server](https://github.com/github/github-mcp-server) - GitHub's maintained MCP server. It can read repository content and, when enabled, manage issues, pull requests, and other GitHub resources.
* [Brave Search MCP](https://github.com/brave/brave-search-mcp-server) - An integration to the Brave Search API, providing comprehensive search capabilities, including web search, local business search, video search, news search, and AI-powered summarization.
* [Filesystem MCP](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem) - Allows AI models to interact with a local or remote computer's file system, enabling it to read and write files, manage directories, search and organize files and retrieve metadata.
* [Aspire MCP](https://aspire.dev/dashboard/mcp-server/) - Integrates Aspire into your development AI eco-system, allowing it to query resources, debug with real-time console logs, investigate development time telemetry, and execute resource commands.
* [Playwright MCP](https://github.com/microsoft/playwright-mcp) - Enables AI tools to interact with web browsers through structured accessibility snapshots, allowing them to navigate pages, interact with elements, fill forms, and execute browser automation without requiring screenshots or vision models.
* [Postgres MCP](https://github.com/crystaldba/postgres-mcp) - Connects AI tools to PostgreSQL and provides schema exploration and SQL execution with a restricted read-only mode.
* [MySQL MCP](https://github.com/benborla/mcp-server-mysql) - Provides AI tools with access to MySQL databases for schema exploration, query execution, and data analysis.

## Configuring MCP Servers

MCP servers are configured via JSON configuration files, with the location of them depending on your chosen client, for example, for Claude Desktop:

Location:

* macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
* Windows: `%APPDATA%\Claude\claude_desktop_config.json`

The examples below use the `mcpServers` shape used by Claude Desktop. Other MCP hosts may use different configuration keys or support different transports, so follow your host's setup guide. These examples start local Docker servers; install Docker first. Keep credentials out of shared configuration and source control. Make the named variables available to the host process through your operating system's secret store or protected environment before starting the host.

### GitHub MCP Server (read-only)

```json
{
  "mcpServers": {
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN", "ghcr.io/github/github-mcp-server", "stdio", "--toolsets=repos", "--read-only"]
    }
  }
}
```

Provide `GITHUB_PERSONAL_ACCESS_TOKEN` to the host process through a secret store or protected environment variable; do not paste a real token into a checked-in config. Grant the credential access only to the repositories and read operations the task needs. The server's `--read-only` flag removes write tools, but does not reduce the credential's underlying GitHub permissions; use a read-only, repository-scoped credential where possible. Avoid organization-wide access unless required.

**Check the connection:** Ask the MCP client to call `get_file_contents` for a known file in a repository the credential can read. Success returns the file contents (or a directory listing if a directory was requested). A permission or authentication error means the connection or credential needs attention. This read-only check does not change repository data.

### PostgreSQL MCP (restricted)

```json
{
  "mcpServers": {
    "postgres": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "-e", "DATABASE_URI", "crystaldba/postgres-mcp", "--access-mode=restricted"]
    }
  }
}
```

Provide `DATABASE_URI` to the host process through a secret store or protected environment variable. Use TLS when connecting remotely and a dedicated database role that can connect to only the required database and has `USAGE` on only the needed schemas and `SELECT` on only the needed tables or views. Do not grant write privileges, ownership, or elevated roles for read-only work. Restricted mode uses read-only transactions and limits query execution time; it is an additional safeguard, not a replacement for database permissions. The project documents a limitation: unsafe stored-procedure languages enabled in the database may circumvent its read-only protections. Do not expose such languages for this connection, and do not treat restricted mode alone as a security boundary.

**Check the connection:** Call `list_schemas` to confirm that the expected permitted schema appears. Then call `execute_sql` with `SELECT current_database() AS database_name, current_user AS role_name;`. Success returns one row naming the connected database and role. If access fails, review the connection URI and the role's database, schema, and table grants. These checks only read metadata and session identity.

The host's environment-variable inheritance varies. Configure these variables using your host's documented secret mechanism; never put real credentials in a shared example. The server flags above are for the official local Docker servers and may need adapting to your MCP host.
